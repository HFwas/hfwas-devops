## 1. 结论

- 当前 SQLite 架构适合单项目 1k–10 万事项、总事项百万级、几十到几百活跃用户。
- 10M 事项、多人并发、单项目热数据的场景不可用：列表秒级、深分页秒到分钟、LIKE/JSON 扫描不可接受。
- 已确认切换 MySQL 8 + Flyway；容量目标通过索引、分页与查询改造达成。

## 2. 基准方法

| 项 | 值 |
|----|----|
| 机器 | Apple M1，8GB，本地 SSD |
| 数据库 | SQLite 3.47（生产配置：rollback journal、`busy_timeout=5000`） |
| 数据 | 1000 万 `pm_work_item`，约 2.97GB；热项目 500 万，其余分散到 9999 个项目 |
| Schema | 复制当时 PM 表与索引（未加组合索引前） |
| 查询 | 模拟列表 COUNT、排序、筛选、深分页、LIKE、JSON |
| 说明 | 直连 SQLite，不含 JVM/Tomcat/Keycloak/网络；生产 PVC 通常更慢 |

## 3. 单表查询实测

| 场景 | 数据量 | 耗时 |
|------|--------|------|
| 点查 `(project_id,item_no)` | 千万级表 | `<0.1ms` |
| 小项目列表 | 约 500 行 | `0.8–1.2ms` |
| 热项目按 `create_time` 排序 | 同类型 71.4 万行 | `0.4–0.5s` |
| 热项目按 `update_time` 排序 | 71.4 万行 | `0.45s`（热缓存）～`3.3s`（冷缓存） |
| 同条件 COUNT | 71.4 万行 | `0.4–1.0s` |
| `OFFSET 1000000` | 71.4 万行 | `6.0–6.7s` |
| `LIKE '%无命中%'` | 71.4 万行 | `3.7s` |
| `json_extract` 无命中 | 71.4 万行 | `4.1s` |
| 全表 COUNT | 1000 万 | `56ms` |
| 热项目全量 COUNT | 500 万 | `282ms` |

单项目 1000 万时按同类型约 140 万行估算：列表 `1–2s`、COUNT `1–2s`、深分页 `12s+`、LIKE/JSON `8–15s`；缓存与磁盘状态会更差。

## 4. 并发与 TPS 实测

| 场景 | 结果 |
|------|------|
| 小项目读，50 并发 | 约 `2,400 QPS`，P95 `52ms`（WAL） |
| 热项目重查询 | 单次 `0.4–3.3s`；Hikari 10 连接下约 `3–25 QPS` |
| WAL 写入 1/4/10 并发 | `1,447 / 2,352 / 764 TPS`，10 并发 P95 `66ms` |
| 默认 journal 写入 4/10 并发 | `1,378 / 591 TPS`，10 并发 P95 `70ms` |

写入是本地 NVMe、极小事务的理想值；生产网络盘通常慢 5–50 倍。

## 5. 并发用户估算

活跃用户数 ≈ `TPS × 用户思考时间`。

| 项目规模 | 列表 TPS | 5–10 秒思考时间下的活跃用户 | 问题阈值 |
|----------|----------|------------------------------|----------|
| 每项目 1k 行 | 数百–2k | 500–2000 | 约 10 个并发重查询开始排队 |
| 每项目 10 万行 | 数十–200 | 200–800 | P95 超过 1 秒 |
| 每项目 100 万行 | 3–25 | 20–150 | 列表 1–3 秒 |
| 单项目 1000 万 | 1–5 | 10–50 | 列表秒级、搜索十秒级，不可用 |

写入侧 SQLite 单写者：约 10–20 个并发编辑开始排队，20–50 个并发写可能触发 `busy_timeout`。

## 6. 迁移后的目标

MySQL 8 通过以下措施达到 10M 容量：

- `BIGINT` 主键/外键；索引列 `VARCHAR`，禁止 TEXT 索引；
- 组合索引：`pm_work_item(project_id, del_flag, update_time)`、`(project_id, type_code, del_flag, create_time)`、`assignee_id`、`sprint_id`、`parent_id`；
- keyset 分页替代大 OFFSET；
- COUNT 缓存/近似计数，避免每页全量 COUNT；
- 自定义字段后续落值表或生成列，避免 `json_extract` 全扫；
- 搜索接 MySQL FTS/OpenSearch；
- 10M 基线：项目列表 P95 < 200ms（见迁移 AC-10）。
