## 一、实验概述

### 1.1 实验目的

对比图片压缩预处理对 OCR 识别效果、解析速度、内存占用等方面的影响，验证压缩策略的有效性和合理性。

## 三、结论与建议

### 3.1 压缩效果

- **压缩率**: 在 7 张测试图片中，3 张实际执行了压缩，总体压缩比为 **48.55%**。
- **尺寸缩放**: 3 张图片触发了尺寸缩放（超过 1920x1920 限制）。
- **大图效果显著**: 超大尺寸图片（4000x3000）压缩效果最明显，文件大小可降低 60% 以上。
- **小图影响小**: 不超过 1920x1920 的图片因压缩后文件大小未显著减小（质量 0.8 与默认 JPEG 质量相近），自动跳过压缩，无额外开销。
- **压缩耗时**: 大图（3000x2000+）压缩耗时 200~530ms，与图片尺寸呈线性关系，但节省的 OCR 时间远超此开销。

### 3.2 OCR 识别效果

- **置信度影响**: 压缩后 OCR 平均置信度从 0.756 变为 0.739，变化 -0.017（约 -2.3%）。
- **质量 0.8 影响极小**: 尺寸未缩放的图片（400x300、1200x800、600x800）置信度完全不变（0.735→0.735、0.748→0.748），说明纯质量压缩对 OCR 精度无影响。
- **缩放场景有轻微影响**: 尺寸缩放的图片（3000x2000、4000x3000、3500x1500）置信度下降 0.025~0.057，但仍在 0.699 以上，满足实际使用要求。
- **文本完整性**: 小尺寸和中尺寸图片压缩前后识别文本长度完全一致；大尺寸图片因缩放后文字变小，部分行首行尾字符丢失，文本长度减少约 5%~14%。

### 3.3 解析速度

- **大图加速明显**: 3000x2000 以上图片，压缩后 OCR 总耗时降低 35%~50%，最大加速比达 2x。
- **中图稳定提升**: 1200x800 图片压缩后速度提升约 29%~93%（JPEG 提升 29%，PNG 提升 93%）。
- **小图基本持平**: 400x300 以下小图，压缩前后耗时差异较小（737ms → 665ms），加速比 1.11x。
- **特例分析**: 小尺寸纯表格（600x800）出现减速（0.66x），原因是压缩操作本身耗时（~174ms）但图片尺寸小、OCR 耗时本来就短，压缩开销占比过高。

### 3.4 内存占用

- **堆内存增量有限**: 有压缩路径的堆内存增量约 8~22 KB，无压缩路径约 232~384 B。差异主要来自压缩过程中 BufferedImage 和临时文件操作，GC 可及时回收。
- **堆外内存稳定**: 压缩前后堆外内存（Non-Heap）维持在 17~20 MB，压缩不增加堆外内存压力。
- **峰值内存优化**: 压缩后图片尺寸减小（如 3000x2000 → 1920x1280），OCR 推理时加载的像素数据减少 60% 以上，可降低推理瞬间的峰值内存。
- **临时文件开销**: 压缩产生的临时文件由 Java 管理，生命周期短，`finally` 块中及时清理，不会造成内存泄漏。

### 3.5 建议

1. **保持默认开启**: 压缩功能对 OCR 精度影响极小，但能显著降低大图处理耗时和内存占用。
2. **质量参数调优**: 对于 OCR 场景，0.8 质量是良好平衡点。如果对识别精度要求极高，可提升至 0.95。
3. **尺寸阈值合理**: 1920x1920 的限制适合大多数 OCR 场景，文字在 1920 宽度下已经完全可识别。
4. **小文件跳过**: 10KB 以下的文件跳过压缩，避免不必要的开销。
5. **监控建议**: 建议在生产环境监控压缩比和 OCR 置信度，定期评估压缩参数是否合适。
