## 1. 背景与目标

### 1.1 现状

当前 PM 前端只有「页头 + 类型按钮 + 固定 5 列表格 + 上一页/下一页」：

- 搜索仅支持标题 LIKE，无组合筛选、无保存视图；
- 列固定为编号 / 标题 / 状态 / 优先级 / 更新时间，无法按角色切换关注字段；
- 分页无总数、每页条数、跳页；
- 没有批量操作、行内快捷菜单、快速预览；
- 项目列表与工作项列表各自拼装，缺少统一的列表页骨架。

### 1.2 目标

| 编号 | 目标 | 可验证结果 |
|------|------|-----------|
| G1 | 统一列表组件 | 项目列表与工作项列表共用同一套 `ListPageShell + FilterBar + DataTable + Pagination` |
| G2 | 三秒读懂列表 | 编号、类型、标题、状态、负责人、优先级、截止时间在一屏内可读 |
| G3 | 查询可分享 | 搜索、筛选、排序、列配置、分页全部写入 URL，刷新与回退不丢状态 |
| G4 | 视图可复用 | 支持系统视图 + 用户保存视图，切换视图即切换查询与列 |
| G5 | 展示可配置 | 列显示/顺序、密度、分组三项可调，配置随视图保存 |
| G6 | 操作可批量 | 勾选后出现批量栏，支持改状态、改负责人、删除（危险操作二次确认） |
| G7 | 状态完整 | 默认 / 空态 / 加载 / 失败 / 无权限 / 校验失败 / 大数据量 / 长文本全部可直达 |

### 1.3 非目标（本版不做）

- 看板、甘特图、迭代燃尽图、工时与报表；
- 新的权限模型与字段级权限；
- 后端新增查询能力（首版只消费现有 `QuerySpec` 与分页接口）；
- 移动端适配（仅覆盖 1280 / 1440 桌面）；
- 前端技术栈迁移（继续 React 19 + Tailwind v4 + shadcn/ui）。

> 注：`docs/pm/pm-design.md` 记录的 Vue 3 + Naive UI 技术栈已过时，与 `AGENTS.md` v0.24 冲突。本设计以 `AGENTS.md` 与现有 `frontend/` 实现为准；PM 设计文档在实现阶段同步修订。

## 2. 业界调研结论

检索 Jira Issue Navigator / All work、PingCode 列表视图、Linear 后归纳：

| 模式 | Jira | PingCode | Linear | 本设计取舍 |
|------|------|----------|--------|-----------|
| 视图入口 | Issue Navigator + 保存的筛选器 | 项目内「视图」页签，按角色拆分 | 团队视图 + 自定义视图 | 页头下方 `ViewTabs`，系统视图置前，用户视图可另存 |
| 搜索 | 基础搜索 + JQL 高级搜索 | 顶部搜索 + 字段筛选 | 单框即时搜索 + 命令面板 | 单框即时搜索 + 「筛选」面板里的组合条件，高级 JQL 延后 |
| 筛选呈现 | 下拉筛选器，条件可保存 | 筛选条件 + 字段配置 | 筛选 chip 行 | 已选条件渲染为可删除的 chip 行，条件多时折叠 |
| 列配置 | Columns 菜单显示/隐藏/排序 | 自定义表头字段 | 视图内列设置 | `DisplayMenu` 内列显示、顺序恢复默认、密度 |
| 批量 | 全选最多 1000 条，批量变更 | 批量修改状态/负责人 | 多选后浮动工具栏 | 首版仅当前页全选，浮动 `BulkActionBar` |
| 分页 | 分页器 + 每页条数 | 分页器 | 虚拟滚动为主 | 保留服务端分页，补总数、每页条数、跳页 |
| 行详情 | 行点击进入详情，支持侧栏预览 | 右侧抽屉 | 详情页/侧栏 | 标题进详情页，行「预览」开抽屉，URL 保留列表状态 |

结论：PM 列表应是**工作台**而不是「字段仓库」。统一组件必须同时承载视图、查询、展示和批量四类配置，而不是只封装一张表。

## 4. 统一组件模型

全部落在 `frontend/src/components/console/`（业务无关）与 `frontend/src/modules/pm/components/`（PM 语义）。

| 组件 | 职责 | 关键 props | 复用页面 |
|------|------|-----------|---------|
| `ListPageShell` | 列表页骨架：页头、视图页签、工具栏、条件行、内容、分页槽 | `header` `views` `toolbar` `filters` `children` `footer` | P01、P08、后续容器/流水线列表 |
| `SearchInput` | 防抖搜索，`/` 聚焦，Esc 清空，带清除按钮 | `value` `onChange` `debounce=300` `placeholder` | 所有列表 |
| `FilterBar` | 条件 chip 行 + 「添加筛选」入口 + 清空全部 | `conditions` `onRemove` `onClear` `onAdd` | P01、P08 |
| `FilterBuilder` | 组合条件面板：字段 / 运算符 / 值，AND/OR | `schema` `value` `onApply` | O01 |
| `ViewTabs` | 系统视图与保存视图页签，脏标记，另存为 | `views` `activeId` `dirty` `onSelect` `onSaveAs` | P01 |
| `DisplayMenu` | 列显示/顺序、密度、分组 | `columns` `density` `groupBy` `onChange` | O02 |
| `DataTable`（扩展） | 选择列、可排序表头、粘性表头、密度、空态/错误/骨架 | 在现有 props 上新增 `selectable` `selectedIds` `sort` `density` `stickyHeader` | P01、P08 |
| `BulkActionBar` | 选中后的浮动操作条 | `count` `actions` `onClear` | P01 |
| `Pagination`（扩展） | 总数、每页条数、页码、跳页 | 在现有 props 上新增 `total` `pageSize` `onPageSizeChange` `jump` | 所有列表 |
| `QuickViewDrawer` | 右侧快速预览，保留列表上下文 | `item` `onClose` `onOpenFull` | O03 |
| `StatusPill` / `PriorityIcon` / `TypeIcon` | 状态、优先级、类型的统一语义展示 | 枚举 + 字典 | P01、抽屉、详情 |
| `UserAvatar` | 负责人头像 + 姓名，支持未分配 | `user` `size` | 列表、抽屉 |
| `EmptyState` / `ErrorState` / `NoPermissionState` | 统一空态、失败、无权限 | `title` `description` `action` | 所有列表 |
| `useListUrlState` | 查询状态与 URL 双向同步 | query / filters / sort / page / size | 所有列表 |

### 4.1 组件约束

1. 业务页面不得自写表格、搜索框、分页器；只允许通过上述组件组合。
2. 颜色、圆角、间距全部来自 `--background` / `--primary` / `--muted` / `--border` / `--radius` 语义 token。
3. 状态不仅靠颜色：状态 pill 带文案，优先级带图标 + 文案，负责人带姓名。
4. 表格列宽固定策略：编号 96、类型 88、标题弹性、状态 104、优先级 88、负责人 140、截止 112、更新 136。
5. 所有列表查询条件变化时，页码重置为第 1 页。

## 5. 关键交互

### 5.1 搜索

- 输入后 300ms 防抖，写入 URL `q`；回车立即查询。
- 有值时显示清除按钮；Esc 清空并保持焦点。
- 无结果时展示「没有匹配的工作项」，保留筛选条件并提供「清空搜索」。

### 5.2 筛选

- 「筛选」打开 `FilterBuilder`：字段（状态/类型/优先级/负责人/截止时间/标签）、运算符、值。
- 条件之间默认 AND，可切换 OR；首版不支持嵌套分组（原型展示分组入口并标注后续）。
- 应用后条件渲染为 chip：`状态 = 进行中 ×`；多个条件超过一行时折叠为「+3 个条件」。
- 条件变化立即查询并重置页码。

### 5.3 视图

- 系统视图：全部、我的待办、本周到期、最近更新。
- 用户视图可基于当前查询「另存为」，命名后出现在页签末尾。
- 当前视图被修改后页签显示 `•` 脏标记，提供「保存」与「重置」。
- 视图切换保留列的显示配置与密度。

### 5.4 展示配置

- 列设置：勾选显示、拖拽排序（原型提供上下移动按钮）、恢复默认。
- 密度：紧凑（行高 36）/ 标准（44）。
- 分组：无 / 状态 / 负责人 / 优先级；首版原型展示分组后的分段表头，不实现折叠动画。

### 5.5 排序

- 点击表头在 升序 → 降序 → 默认 间切换，当前列显示箭头。
- Shift+点击追加多列排序；URL 记录 `sort=priority:ASC,updated:DESC`。
- 首版默认按「更新时间倒序」。

### 5.6 分页

- 服务端分页，默认每页 10，可选 10 / 20 / 50 / 100。
- 显示「共 128 条 · 第 3 / 7 页」，支持上一页 / 页码 / 下一页 / 跳至第 N 页。
- 筛选、搜索、排序、每页条数变化时回到第 1 页。
- 页数多时省略号收拢（沿用现有 `Pagination` 算法）。

### 5.7 选择与批量

- 表头复选框全选当前页；选中行高亮。
- 选中后出现 `BulkActionBar`：批量改状态、批量改负责人、导出、删除。
- 跨页选择首版不支持；选择后翻页会清空，并在批量栏文案中注明「已选当前页 N 项」。
- 删除必须二次确认，按钮文案写明「删除 N 个工作项」。

### 5.8 行操作与快速预览

- 点击标题进入工作项详情页。
- 行悬停显示「预览」「更多」，更多菜单含复制编号、复制链接、改状态、删除。
- 预览打开右侧抽屉（480px），展示标题、状态、负责人、优先级、截止时间、描述、最近动态；底部「打开完整详情」。
- 抽屉打开时 URL 增加 `overlay=detail&id=...`，关闭后列表状态不变。

### 5.9 键盘

| 按键 | 行为 |
|------|------|
| `/` | 聚焦搜索（输入框内不触发） |
| `↑` / `↓` | 在行间移动焦点 |
| `x` | 切换当前行选择 |
| `Enter` | 打开当前行详情 |
| `Esc` | 关闭抽屉/面板，或清空搜索 |

### 5.10 新建

- 主按钮「新建工作项」，弹窗包含类型、标题、状态、负责人、优先级、截止时间。
- 标题必填；校验失败在字段下方显示错误，并在弹窗顶部汇总。
- 创建成功后关闭弹窗、回到第 1 页、保留当前视图。

## 6. 状态矩阵

| 状态 | 触发 | 表现 | 参数 |
|------|------|------|------|
| 默认 | 有数据 | 完整列表、分页、操作可用 | `#/list` |
| 空态 | 查询无结果或项目无数据 | 插画位 + 文案 + 主行动 | `state=empty` |
| 加载 | 首次加载 | 表头保留 + 6 行骨架 | `state=loading` |
| 失败 | 请求失败 | 错误说明 + 重试按钮，区分网络/业务 | `state=error` |
| 无权限 | 只读或无访问权 | 锁图标 + 说明，隐藏新建与批量 | `state=permission` |
| 校验失败 | 新建表单非法 | 字段级错误 + 顶部汇总 | `overlay=create&state=invalid` |
| 大数据量 | 128 条、长标题、多位数编号 | 列宽稳定、省略号、分页边界 | `state=dense` |
| 长文本 | 超长标题、超长负责人名 | 单行省略，悬停提示 | `state=long` |
| 危险操作 | 批量删除 | 二次确认，写明数量与后果 | `overlay=delete` |
| 选中态 | 勾选行 | 批量栏出现，行高亮 | `state=selected` |

## 7. 接口与数据结构

### 7.1 复用现有接口

| 场景 | 接口 | 说明 |
|------|------|------|
| 工作项列表 | `POST /pm/work-items/page` | 请求体即 `QuerySpec`：`conditions` / `groups` / `sort` / `pageNo` / `pageSize` |
| 字段 Schema | `GET /pm/projects/{id}/issue-types/{type}/fields` | 决定可筛选字段与列标题 |
| 状态选项 | `GET /pm/projects/{id}/status-options` | 状态字典 |
| 保存视图 | `PmSavedView`（`querySpec` + `columns`） | 视图持久化 |
| 项目列表 | `POST /pm/projects/page` | 复用同一列表骨架 |

### 7.2 需要的增量能力（标 ASSUMPTION，待后端确认）

| 编号 | 需求 | 现状 | 建议 |
|------|------|------|------|
| A1 | 列表返回负责人显示名 | `PmWorkItem` 仅有 `assigneeId` | 分页响应补 `assigneeName` / `assigneeAvatar`，或在项目成员接口批量解析 |
| A2 | 截止时间 | `PmWorkItem` 无截止时间列 | 作为系统字段 `end_time` 加入时间字段与查询条件 |
| A3 | 批量操作 | 无批量接口 | 复用逐条更新，首版前端串行调用；后续补 `POST /pm/work-items/batch` |
| A4 | 保存视图接口 | 类型已定义，接口未在 `pm-api.md` 列表 | 实现前确认路由 |
| A5 | 全选全部结果 | 服务端分页 | 首版仅当前页，避免引入新查询语义 |

查询映射：

```text
q            → conditions[{ field: "title", operator: "LIKE", value }]
status       → conditions[{ field: "status", operator: "IN", value: [...] }]
assignee     → conditions[{ field: "assignee_id", operator: "IN", value: [...] }]
due          → conditions[{ field: "end_time", operator: "BETWEEN", value: [from, to] }]
sort         → sort[{ field, order }]
pageNo/size  → pageNo / pageSize
```

## 8. 兼容性与迁移

- 技术栈：React 19 + TypeScript + Vite + Tailwind v4 + shadcn/ui；继续使用 TanStack Query 管理服务端状态，Zustand 管理跨页客户端状态。
- 现有 `DataTable` / `Pagination` 采用**扩展而非重写**，保证容器、流水线、接口测试等既有列表不受影响；新增能力通过可选 props 开启。
- `ListPageShell` 先在 PM 落地，稳定后再迁移到其他模块；迁移不在本功能范围。
- 路由沿用现有 `/pm/projects/:projectId/items/:typeCode`，详情抽屉不新增路由，只增加 `overlay` 查询参数。
- 列表状态全部落在 URL，刷新、分享、浏览器回退行为与当前一致。
- 不引入新字体、新颜色体系；沿用 `--radius: 0.5rem` 与冷蓝主色。

## 10. 风险与待确认

| 风险 | 影响 | 应对 |
|------|------|------|
| 后端缺少负责人显示名与截止时间 | 列表列无法直接落地 | 原型先用样例；实现前确认 A1/A2 |
| 保存视图接口未落地 | 视图页签只能做前端临时态 | 首版视图存 localStorage，接口就绪后切换 |
| 列配置与字段 Schema 的映射关系 | 自定义字段无法出现在列设置 | 字段 Schema 的 `showInList` / `listOrder` 作为默认列集 |
| 批量操作逐条调用 | 大数据量下耗时长 | 限制单次 50 条并显示进度，后续补批量接口 |
| 分组视图与分页组合语义 | 分组跨页不连续 | 首版分组仅对当前页生效，文案注明，后续改服务端分组 |
