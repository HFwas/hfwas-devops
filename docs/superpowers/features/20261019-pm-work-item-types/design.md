## 1. 背景与目标

### 1.1 现状

- 后端已提供事项类型 CRUD：`POST /pm/meta/types`、`/save`、`/delete`，字段包含 `code` / `name` / `color` / `icon` / `sortOrder` / `enabled`。
- 项目启用方案由 `/pm/projects/issue-types/list|save` 全量维护。
- 字段布局与工作流已可配置：`/pm/fields/layout/get|save`、`/pm/status/workflow/*`。
- 前端只有列表页的类型按钮与工作流页，**没有事项类型管理页面**，无法新建、停用、删除、配置自定义类型。
- 当前种子类型仅 4 个（需求/任务/缺陷/测试用例），缺少用户要求的**迭代**。

### 1.2 目标

| 编号 | 目标 | 可验证结果 |
|------|------|-----------|
| G1 | 内置类型开箱可用 | 需求、任务、缺陷、迭代、测试用例 5 个内置类型默认启用，不可删除 |
| G2 | 自定义类型可管理 | 列表可见来源、启用状态、字段数、工作流、使用量；支持新建、复制、编辑、停用、删除 |
| G3 | 模板化创建 | 新建时从 5 个内置类型中选模板，继承字段布局与工作流，降低配置成本 |
| G4 | 配置闭环 | 一个页面内完成基本信息、字段与布局、工作流、预览四步配置 |
| G5 | 项目范围可控 | 可单独维护当前项目启用哪些类型及其顺序，不影响其他项目 |
| G6 | 危险操作可解释 | 删除、停用、切换模板前说明影响范围；被引用时禁止删除并给出替代动作 |
| G7 | 状态完整 | 默认 / 空态 / 加载 / 失败 / 无权限 / 校验失败 / 大数据量 / 长文本全部可直达 |

### 1.3 非目标

- 不实现工作流画布编辑器（复用现有工作流页，本页只选模板与预览）；
- 不实现字段类型注册与字段新建（复用现有字段配置页，本页只做字段显隐与顺序）；
- 不实现跨租户的全局管理员隔离；
- 不实现类型层级（Epic → Story → Sub-task）配置；
- 不实现看板列映射与自动化规则。

## 2. 业界调研结论

| 模式 | Jira | PingCode | 本设计取舍 |
|------|------|----------|-----------|
| 内置与自定义 | 内置类型可改图标/名称，不可删除；自定义需管理员权限 | 内置类型不可删除/编辑；自定义类型归属内置分组 | 内置 5 类**不可删除、不可改 code**；允许图标/颜色/名称只读展示，字段与工作流可配置 |
| 类型方案 | Issue Type Scheme 决定项目可见类型与顺序 | 项目「配置中心 → 工作项」按项目模型配置 | 项目启用范围独立抽屉，全量保存 |
| 新建流程 | 先建类型，再加入 scheme，再配字段/工作流 | 在项目配置中心直接新建，配置状态机与属性 | 合并为四步向导，默认同时启用当前项目 |
| 删除语义 | 有事项引用时不可删除，只能隐藏 | 内置不可删；自定义被引用时停用 | 被引用 → 禁止删除，引导停用；无引用 → 二次确认删除 |
| 模板 | 无原生模板，多为复制 | 项目模型内置类型组合 | 以 5 个内置类型为模板，复制字段与工作流 |
| 字段配置 | Screens + field configuration | 类型独有属性 | 字段列表 + 显示位置（列表/创建/详情）+ 顺序 + 必填 |

结论：类型管理页要同时回答「有哪些类型」「项目能用哪些」「每个类型的字段和工作流是什么」三个问题，不能只做一张 CRUD 表。

## 5. 关键交互

### 5.1 内置类型规则

- 5 个内置 code：`requirement` / `task` / `bug` / `iteration` / `test_case`。
- 不可删除、不可修改 `code`；名称、图标、颜色以系统定义为准，列表只展示锁标识。
- 可配置字段布局与工作流；可在项目范围中被停用。
- 若某项目停用内置类型，已有事项仍可打开，只是新建菜单不再出现。

### 5.2 自定义类型

- 新建时必须选择模板（默认「任务」），模板决定初始字段与工作流。
- 编码唯一，创建后不可修改；停用后可重新启用。
- 有事项引用时禁止删除，只能停用；无引用时二次确认删除。
- 复制类型生成新的 code 与名称，字段、工作流、项目范围一并复制。

### 5.3 启用与项目范围

- 全局 `enabled` 控制类型是否在所有项目可用；项目 scheme 控制当前项目可见集合与顺序。
- 开关切换立即保存全局状态；项目范围抽屉保存当前项目 scheme。
- 关闭开关前二次确认，写明「已有 N 个事项保留」。

### 5.4 字段与布局

- 字段来源分「系统字段」与「自定义字段」；系统字段不可从类型中移除，只能控制显示位置。
- 三个显示位置：列表列、创建表单、详情页；必填只对创建表单生效。
- 顺序通过上移/下移调整（原型不实现拖拽，生产用 dnd-kit）。
- 切换模板时提示重置；选择「保留当前配置」则不覆盖。

### 5.5 工作流

- 提供 5 个模板：任务默认、需求评审、缺陷修复、迭代、空白。
- 预览展示状态与流转箭头；「打开高级工作流编辑器」跳转既有页面。
- 空白模板初始只有「待办 / 进行中 / 已完成」三态。

### 5.6 预览

- 新建表单预览按创建字段与必填标记渲染。
- 列表行预览按列表字段渲染，显示图标、编号、标题、状态、负责人。

## 6. 状态矩阵

| 状态 | 触发 | 表现 | 参数 |
|------|------|------|------|
| 默认 | 有 9 个类型 | 指标、页签、表格完整 | `#/types` |
| 空态 | 无自定义类型 | 空态 + 新建 + 模板入口 | `#/types?state=empty` |
| 加载 | 首次加载 | 6 行骨架 | `#/types?state=loading` |
| 失败 | 请求失败 | 错误说明 + 重试 | `#/types?state=error` |
| 无权限 | 只读成员 | 隐藏新建/删除/启停，保留查看 | `#/types?state=permission` |
| 校验失败 | 名称空、编码重复 | 顶部汇总 + 字段错误 | `#/types/new?state=invalid` |

| 危险操作 | 删除 | 二次确认或阻止 | `overlay=delete&blocked=1` |
| 停用 | 关闭启用 | 二次确认 | `overlay=disable` |
| 模板切换 | 基本信息切换模板 | 重置提示 | `overlay=template-reset` |

## 7. 接口与数据

### 7.1 复用接口

| 场景 | 接口 | 说明 |
|------|------|------|
| 类型列表 | `POST /pm/meta/types` `{ includeDisabled }` | 管理页传 `true` |
| 新建/更新 | `POST /pm/meta/types/save` | `id`、`code`、`name`、`color`、`icon`、`sortOrder`、`enabled` |
| 删除 | `POST /pm/meta/types/delete` `{ code }` | 有引用时返回业务错误 |
| 项目启用 | `POST /pm/projects/issue-types/list|save` | 全量替换 typeCodes |
| 字段 Schema | `GET /pm/projects/{id}/issue-types/{type}/fields` | 字段清单与必填 |
| 字段布局 | `POST /pm/fields/layout/get|save` | listFields / searchFields / createFields / detailTabs |
| 工作流 | `POST /pm/status/workflow/get|save` | 状态与流转 |
| 类型方案导入导出 | `POST /pm/issue-type-schemes/*` | 复制/模板继承可复用 |

### 7.2 增量能力（ASSUMPTION）

| 编号 | 需求 | 现状 | 建议 |
|------|------|------|------|
| A1 | 内置标识 | 接口无 `builtIn` 字段 | 后端补 `builtIn` / `systemFlag`，前端回退按 5 个内置 code 判断 |
| A2 | 使用中事项数 | 类型列表无统计 | 响应补 `workItemCount`，或在列表接口批量聚合 |
| A3 | 字段数 | 无 | 可由字段 Schema 聚合，或类型接口补 `fieldCount` |
| A4 | 类型描述 | `PmWorkItemType` 无 `description` | 后端补字段 |
| A5 | 模板来源 | 无 `basedOn` | 后端补 `templateCode`，前端仅展示 |
| A6 | 按模板复制工作流 | 新建时后端固定复制 `task` 工作流 | 改为按 `templateCode` 复制，或前端保存后调用工作流保存接口 |
| A7 | 迭代内置类型 | 仅 4 个种子类型 | 新增 `iteration` 种子与默认工作流 |
| A8 | 删除前置校验 | 删除失败只返回业务错误 | 返回 `workItemCount` 便于前端展示阻止原因 |
| A9 | 项目范围排序 | save 只接收 typeCodes | 数组顺序即排序，后端按顺序写 `sortOrder` |

## 8. 兼容性与迁移

- 技术栈：React 19 + TypeScript + Vite + Tailwind v4 + shadcn/ui。
- 路由：项目设置新增 `settings/types` 与 `settings/types/new|edit`，不影响现有 `settings/workflow/:typeCode`。
- 数据迁移：
  - 新增 `iteration` 类型种子，需新增 SQL 迁移文件（当前最大为 17，使用 18），禁止修改已有迁移文件。
  - `embedded` 模式的 `SqliteSchemaInitializer` 同步补种子。
  - 为现有项目 scheme 追加 `iteration`（可配置为默认启用）。
- 现有 4 类事项不受影响；新增类型的 `code` 与内置集合分开校验。
- 内置类型的判断在后端补字段前使用前端常量兜底，后端就绪后删除兜底。

## 10. 风险与待确认

| 风险 | 影响 | 应对 |
|------|------|------|
| 后端无 `builtIn` 字段 | 前端只能按 code 判断，存在误判 | 常量兜底 + 尽快补字段 |
| 无使用量统计 | 删除阻止与停用说明缺少数据 | 后端补聚合，或前端按需查询 |
| 新建类型固定复制 task 工作流 | 模板工作流不生效 | 前端保存后调用工作流保存接口，或后端调整 |
| 类型全局创建、项目内管理 | 用户在项目设置里新建会影响其他项目 | 摘要卡明示「全局类型」，启用范围默认仅当前项目 |
| 字段布局与字段配置页职责重叠 | 两个入口可能冲突 | 本页只做显示位置与顺序，字段定义仍在字段配置页 |
| 迭代作为事项类型 | 迭代通常是容器而非工作项 | 按用户要求内置；后续若改为容器，需要单独设计 |
