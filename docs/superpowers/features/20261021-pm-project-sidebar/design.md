## 1. 背景与目标

### 1.1 现状

- PM 产品侧栏只有「项目」和「项目监控」两个入口。
- 进入某个项目后，侧栏仍是产品级菜单；项目内的事项类型、看板、工作流入口以页面顶部按钮呈现，切换类型要回到列表页顶部。
- 「项目监控」只是项目列表的只读副本，链接到看板，没有独立指标或趋势，属于占位入口。

### 1.2 目标

| 编号 | 目标 | 可验证结果 |
|------|------|-----------|
| G1 | 移除项目监控 | 侧栏、路由、面包屑、页面文件中不再出现「项目监控」/`/pm/monitor` |
| G2 | 进入项目后展示项目内菜单 | 访问 `/pm/projects/:projectId/**` 时，左侧栏显示项目上下文菜单 |
| G3 | 项目菜单由项目启用类型驱动 | 类型来自 `POST /pm/projects/issue-types/list`，停用类型不展示 |
| G4 | 类型切换在左侧完成 | 点击类型跳转 `/pm/projects/:projectId/items/:typeCode`，当前类型高亮 |
| G5 | 看板与工作流保留类型上下文 | 从任意项目页面进入看板/工作流时使用当前路由的 `typeCode` |

### 1.3 非目标

- 不实现原型中的「迭代看板」「报表」「成员与权限」等尚未落地的页面。
- 不实现类型数量角标（需要后端聚合或额外查询，见 PM 列表配置设计 A6）。
- 不改变看板、工作流页面自身的信息结构。
- 不改动后端接口与数据库。

## 2. 信息架构与路由

```text
/pm/projects                     项目列表（产品菜单：项目）
/pm/projects/:projectId/items/:typeCode        项目菜单：全部项目 + 启用类型 + 看板 + 工作流
/pm/projects/:projectId/items/:typeCode/:id
/pm/projects/:projectId/board/:typeCode
/pm/projects/:projectId/settings/workflow/:typeCode
```

移除：`/pm/monitor` 路由与 `ProjectMonitorPage`。

左侧栏在进入项目后替换产品菜单，沿用容器模块 `ContainerMenu` 的上下文侧栏模式：

| 分组 | 条目 | 目标 |
|------|------|------|
| 项目 | 全部项目 | `/pm/projects` |
| `<项目名称>`（加载前为「工作项」） | 项目启用的每个事项类型 | `/pm/projects/:projectId/items/:typeCode` |
| 视图 | 看板 | `/pm/projects/:projectId/board/:typeCode` |
| 视图 | 工作流 | `/pm/projects/:projectId/settings/workflow/:typeCode` |

`typeCode` 取值顺序：当前路由中的 `typeCode` → 项目启用类型的第一个 → `task`。

## 3. 交互与状态

1. 类型菜单高亮规则：路径等于或位于 `/items/:typeCode` 之下（含事项详情）时高亮。
2. 看板高亮规则：路径以 `/board/` 开头。
3. 工作流高亮规则：路径以 `/settings/workflow/` 开头。
4. 类型加载中显示禁用的「加载类型…」条目；加载失败时该分组为空，看板/工作流仍可用并回退到 `task`。
5. 内置类型使用图标映射（需求 / 任务 / 缺陷 / 测试用例），自定义类型使用通用圆点图标。
6. 页面内容区不再重复渲染类型按钮与「看板 / 工作流」互跳按钮，避免与左侧菜单形成两套导航。

---

## 4. 验收标准

| 编号 | 标准 |
|------|------|
| AC-01 | 侧栏与路由中不再存在「项目监控」和 `/pm/monitor` |
| AC-02 | 访问项目列表时侧栏只显示「项目」 |
| AC-03 | 访问项目内任意页面时侧栏显示「全部项目」、项目名称、启用类型、看板、工作流 |
| AC-04 | 点击类型跳转到对应事项列表，并高亮当前类型；事项详情保持高亮 |
| AC-05 | 看板/工作流链接携带当前 `typeCode` |
| AC-06 | 类型加载中显示加载条目；自定义类型有兜底图标 |
| AC-07 | 列表、看板、工作流页面不再出现重复的类型按钮行 |
