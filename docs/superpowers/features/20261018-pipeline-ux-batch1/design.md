## 1. 背景与目标

审计结论是“功能可用，但操作习惯与成熟 CI 产品存在系统性偏差”。第 1 批只做**不再走错路**的部分：搜索去对地方、返回回到来源、列表不误触、表单错误可见、侧栏分清工作对象与配置、触发方式文案一致、任务类型术语统一。

目标：

1. 用户在流水线页面使用顶栏搜索时，搜的是流水线，不会被带到项目管理。
2. 从列表、运行历史或外部链接进入运行详情后，“返回”回到进入前的位置。
3. 流水线列表整行可点；删除等低频危险操作收进 `⋯` 菜单。
4. 凭证新建表单校验失败时，字段下方与提交动作都有可见反馈。
5. 侧栏把“任务市场 / 凭证”归入“配置”组，与“流水线”工作对象分开。
6. 运行详情触发方式显示中文，不再出现 `MANUAL`。
7. 任务市场统一使用“任务类型”，不再把类型称作“任务”。

## 3. 交互与实现设计

### 3.1 UX-01 全局搜索

**现状**：`shellSearchCopy()` 对非容器页面统一返回“搜索项目名称或编码”，提交固定跳 `/pm/projects`。

**设计**：

1. `ShellSearchCopy.kind` 增加 `'pipeline'`。
2. `pathname === '/pipeline'` 或以 `/pipeline/` 开头时返回：
   - `placeholder: '搜索流水线名称'`
   - `label: '搜索流水线'`
   - `kind: 'pipeline'`
3. `AppShell.onSearch()` 对 `pipeline` 跳转 `/pipeline/pipelines?q=<encodeURIComponent(value)>`。
4. 流水线列表页已从 URL 读取 `q` 并交给服务端 `keyword`，无需新增接口。
5. 空关键字不跳转（沿用现有行为）；回车与点击搜索按钮行为一致。

**边界**：在流水线详情/编辑/运行详情页输入搜索，同样跳列表并带 `q`；不保留当前流水线的上下文。

### 3.2 UX-02 运行详情返回来源感知

**现状**：`PipelineRunDetailPage.tsx:151` 固定 `to=/pipeline/pipelines/:id/history`。

**设计**：

1. 返回按钮改为按钮 + `navigate`，不再使用固定 `Link`。
2. 判定：
   - 读取 React Router 写入的 `window.history.state.idx`；
   - `idx > 0` 表示当前标签页内有应用内历史，执行 `navigate(-1)`；浏览器刷新后若仍保留上一页，`idx` 仍大于 0，此时返回上一页；
   - 否则（直接打开深链接、无上一页）执行 `navigate('/pipeline/pipelines/:pipelineId/history', { replace: true })`。
3. 按钮文案保持“返回”；来源差异由行为体现。
4. 不引入新的 query/state 约定，不改变可分享链接。

**边界**：

- 从列表“最近运行”进入 → 回列表，保留列表的分页与筛选参数。
- 从运行历史进入 → 回历史。
- 从通知/外部直接进入且无应用内历史 → 回该流水线运行历史。
- 在运行详情内点击日志抽屉后关闭，不影响返回目标。

### 3.3 UX-06 凭证表单错误可见

**现状**：`zodResolver` 已产出 `errors`，但表单没有渲染；名称为空点保存时页面无反应。

**设计**：

1. 名称字段下方渲染 `formState.errors.name?.message`，样式 `text-xs text-destructive`。
2. 输入框设置 `aria-invalid` 与 `aria-describedby`，错误文案使用 `role="alert"`。
3. `handleSubmit` 增加 invalid 回调：`form.setFocus('name')`，保证键盘/读屏用户能定位。
4. 表单加 `noValidate`，避免浏览器原生气泡与自定义提示重复。
5. `kind` 为枚举默认值，本期不新增其它字段校验；类型动态字段属于 UX-17。

**边界**：仅名称必填；用户名、密钥保持可选（`KUBECONFIG` 等场景由后端校验）。后端返回错误仍走 toast（本批不改）。

### 3.4 UX-08 列表整行可点与操作收敛

**现状**：`DataTable` 已支持 `onRowClick`，列表页未使用；操作列常驻 4 个按钮，删除常驻。

**设计**：

1. 传入 `onRowClick={(row) => navigate(`/pipeline/pipelines/${row.id}`)}`；`DataTable` 已有的“点击 a/button/input 不触发行点击”规则继续生效。
2. 名称仍保留 `<Link>`，保证键盘 Tab/Enter 可进入详情，并作为可复制链接。
3. 操作列只保留：
   - 主操作：`StartRunButton`（运行）。
   - `⋯` 下拉菜单：编辑、历史、删除。
4. 删除菜单项打开现有 `ConfirmDialog`；`remove.isPending` 时禁用。
5. 操作列宽度从 `220px` 收窄到 `120px`。
6. 阶段预览的圆点补 `title`（现有 `title` 已在容器上，保持），本批不改颜色体系。

**边界**：

- 点击操作列空白区域是否进详情？操作列属于行，除链接/按钮外仍会触发行点击；可接受。
- 下拉菜单渲染在 Portal，不触发行点击。
- 删除确认弹窗打开时不触发行跳转。

### 3.5 UX-09 触发方式统一

**现状**：运行详情 `value={run.trigger}` 直接显示 `MANUAL`；运行历史使用 `triggerLabel()` 显示“手动”。

**设计**：

1. 运行详情引入 `triggerLabel`，`<Field label="触发" value={triggerLabel(run.trigger)} />`。
2. 未知枚举继续回退原文，避免吞掉未来新增触发方式。
3. 不改运行历史。

### 3.6 UX-19 侧栏分组

**现状**：流水线、任务市场、凭证三项平级。

**设计**：

1. `navigation.ts` 的 `pipeline` 作用域拆为两个组：
   - 主组（无标签）：流水线。
   - `配置` 组：任务市场、凭证。
2. 组内顺序、路由、active 判定不变；折叠态 tooltip 由现有 `SidebarMenuButton` 提供。
3. 不改其它产品作用域的菜单。

**边界**：`menuForScope('pipeline').flatMap(items)` 仍返回 `流水线 / 任务市场 / 凭证`，现有测试语义不变。

### 3.7 UX-20 术语第一批

**设计**：任务市场页面内用户可见文案统一为“任务类型”：

| 位置 | 现文案 | 新文案 |
|------|--------|--------|
| 总数 | 共 N 种任务 | 共 N 个任务类型 |
| 空态 | 没有匹配的任务 | 没有匹配的任务类型 |
| 搜索占位/aria | 搜索任务 | 搜索任务类型 |
| 分组 aria | 任务分组 | 任务类型分组 |

流水线运行中的执行单元仍叫“任务”（job）；“任务市场”作为入口名保留。不做全站批量替换，避免改动后端错误文案与类型名。

## 5. 异常与边界

| 场景 | 期望 |
|------|------|
| 流水线页搜索为空 | 不跳转，保持当前页 |
| 搜索关键词含空格/中文 | 编码后写入 `q`，列表按 `q.trim()` 查询 |
| 运行详情刷新后点返回 | 浏览器仍保留上一页时回上一页；无上一页时回该流水线运行历史，不离开应用 |
| 运行详情由外部深链接打开 | 同上 |
| 行点击落在名称链接/运行按钮/`⋯` | 只执行控件自身行为，不重复跳转 |
| 删除请求进行中 | 菜单项 / 确认按钮禁用，避免重复提交 |
| 名称为空提交 | 显示“请填写名称”，聚焦名称输入框，不发请求 |
| 未知触发枚举 | 显示原文 |
| 侧栏折叠 | 配置组仍可展开为图标模式，tooltip 正常 |

## 6. 兼容性与迁移

- 无数据库、后端、接口变更。
- 现有 URL（`/pipeline/pipelines?q=&page=`）保持兼容；新增搜索入口复用同一参数。
- 不改变运行详情链接的可分享性。
- 无 feature flag；前端发布即生效。

## 9. 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| `window.history.state.idx` 在非浏览器/测试环境缺失 | 返回回退到运行历史 | 用可选链与默认 0；测试覆盖 |
| 行点击与操作控件事件冲突 | 误跳转 | 复用 `DataTable` 的交互元素排除规则 + 测试覆盖 |
| 下拉菜单 Portal 与行点击 | 误跳转 | Portal 不在行 DOM 内，测试验证 |
| 侧栏拆组影响其它产品测试 | 回归 | 保持扁平标签序列不变 |
| 术语改动范围失控 | 大量文案 diff | 仅任务市场 4 处，流水线 job 仍称“任务” |
